# Issue #33: inexpensive facts generation

## Scope and behavior to preserve

Use GPT-5.6 Luna as the recommended model for new OpenAI selections. Preserve saved providers/models, the `facts: string[]` HTTP contract, working local models, readable errors, successful server-side caching, and stale-track protection. Do not add dependencies or silently switch to a more expensive model.

OAuth is a separate architecture decision: the documented ChatGPT sign-in route requires a Codex backend and protected account-management controls. Investigate and document that path; implement it here only if selected after the deployment tradeoff is surfaced.

## Observed problems

- Concurrent server cache misses independently call the model for identical tracks.
- Browser session storage has no expiry or generation-configuration identity and bypasses the server's cache policy.
- Server cache keys ignore generation configuration; entries are not bounded or swept, and every update synchronously rewrites the file.
- SDK defaults permit ten-minute requests with two retries; fetch-based providers have no deadline.
- Metadata and most configuration fields are not validated before cache or provider use.
- The OpenAI picker lacks GPT-5.6, requests do not select reasoning effort or structured output, and prompt interpolation uses replacement-string semantics.

## Cleanup and implementation plan

1. Add regressions for concurrent requests, failed shared requests, configuration changes during generation, invalid input, cache eviction/expiry, and layout remounts before changing the affected paths.
2. Use one bounded server cache, keyed by normalized track and generation-affecting configuration. Remove browser result persistence instead of maintaining a second invalidation protocol. Retain the 500 ms track debounce and generation guard; abort stale browser requests without canceling work shared by other displays.
3. Coalesce identical in-flight generations and store a successful result once. Keep cache misses, shared fresh responses, and true cache hits distinct. Old configuration results must never satisfy requests under new settings.
4. Bound cache entries, prune expired data, and persist atomically without rewriting the full file synchronously on each HTTP request. Legacy cache records without configuration provenance may be discarded; saved provider configuration remains unchanged.
5. Keep the compatible Chat Completions endpoint for existing providers. Add Luna/Terra/Sol choices, explicit no-reasoning default for GPT-5.6 facts, strict structured output for those models, and optional advanced reasoning selection. Preserve legacy model behavior.
6. Set deliberate provider deadlines and zero automatic retries, with safe timeout/error handling. Shorten only the default prompt and preserve custom prompts; substitute metadata literally in one pass.
7. Add a reproducible opt-in live evaluation for Luna `none` versus `low`, including usage and latency, without printing credentials or claiming live results from mocked tests.
8. Run lint, typecheck, unit tests, production build, focused browser checks, and independent review. Document remaining OAuth and live-account validation boundaries.

## Additional reported regression

The user observed GPT-5 exhausting a 4096-token completion budget before usable facts. The running server was subsequently configured with GPT-5 Mini and 65,536 tokens, without an explicit reasoning setting. Completion budgets include hidden reasoning. Add an explicit `minimal` default for original GPT-5/Mini/Nano (which do not support `none`), keep `none` for GPT-5.6, preserve explicit saved token caps, and expose model-specific recommended budgets (2048 for GPT-5.6 facts, 8192 for original GPT-5, 1024 elsewhere). These are starting caps, not promises of usage or quality; live evaluation remains the validation boundary.

## Updated catalog policy (2026-09-06)

The user subsequently authorized deprecating older model choices and migrating saved configuration. The current picker uses Luna/Terra/Sol, GPT-5.5, and Astra; finite old app IDs migrate to Luna with cheap reasoning, the GPT-5.6 alias canonicalizes to Sol, and current/custom IDs remain. Explicit valid token caps and custom prompts are retained. This supersedes the initial blanket preservation of old selected OpenAI IDs. Codex subscription-only Spark is excluded from the API provider. The highest `max`/Pro options remain outside this inexpensive-facts scope and the installed SDK's typed request surface.
